# 畸形帧健壮性修复报告

## 结论

| 项目 | 结果 |
| --- | --- |
| 固定回归样本 | 6/6 符合预期 |
| 逐字节截断 + 随机帧变异 | 4217 例，0 崩溃，0 越界，0 超时，0 泄漏 |
| setup/量化表随机变异 | 300000 次，0 崩溃 |
| 数据帧随机变异 | 200000 次，0 崩溃 |
| 合法流输出一致性 | 15/15 流与修复前逐字节一致 |

## 根因与修复

### 1. 截断帧被零填充静默解码

`oc_pack_read*()` 在越过包尾后继续返回 0，原解码器没有把帧级 EOF 传播为
错误，因此截断包可能被当作合法帧。

修复：

- `lib/bitpack.[ch]` 记录实际消费位数，新增 `oc_pack_tell()` 和
  `oc_pack_overrun()`。
- 不能用 Huffman 预读 EOF 判错：合法最后字节的零填充也会触发预读 EOF。
  因此只在实际消费位数超过包长时判为截断。
- `lib/decode.c` 在帧头、编码标志、模式、MV、QI 和 DCT token 每阶段后
  检查 overrun，返回 `TH_EBADPACKET`。
- `lib/dequant.c` 在 setup 量化表读取各阶段检查 overrun，返回
  `TH_EBADHEADER`。

### 2. 非法量化矩阵缺少约束

规范要求 `NBMS <= 384`。原实现接受 9 位字段可表示的全部 512 个矩阵，
并可能继续用被截断的量化范围构造表。

修复：

- `NBMS > 384` 立即返回 `TH_EBADHEADER`。
- 量化范围索引仍要求 `BMI < NBMS`，并在读取量化范围前后检查 EOF。
- 截断的 setup 头在返回错误前不会进入 `th_decode_alloc()`。

### 3. DCT/MV 数据缺少最终边界

损坏 token 可产生越界零游程、零前进 token 或超长 token 索引；模式数据损坏
可让编码块引用无效参考帧或越界 MV。

修复：

- DCT 重建循环要求 `zzi <= 64`；`zzi == 64` 表示合法块尾，`> 64` 报错。
- 每次读取 token 前检查 token 序号和 `dct_tokens` 容量。
- `eob == 0` 且 `zzi` 未前进时返回 `TH_EBADPACKET`，避免死循环。
- MV 解包限制在格式允许的 `[-31, 31]`。
- 重建前检查每个编码块的 `refi` 只能是 GOLD/PREV/SELF，并再次检查 MV。

### 4. 错误偏移

- 新增 `th_decode_headerin_ex()`、`th_decode_packetin_ex()`，负返回值时
  输出包内字节偏移。
- 新增 `TH_DECCTL_GET_ERROR_OFFSET`，可查询最近一次数据包错误偏移。
- 旧 API 行为保持兼容；成功帧的返回值和输出像素不变。

## 合法输出一致性

用修复前提交 `28fd5ec` 构建参考解码器，对 15 个合法流及基线样本比较每一帧
YCbCr：

- 尺寸：32x32、64x48、96x64、128x96、160x120。
- 像素格式：4:2:0、4:2:2、4:4:4。
- 结果：16/16 全部逐字节一致，零差异。

默认启用 x86 汇编的构建与无汇编构建也输出相同哈希。
